# 扫码登录：已批准设计

用户批准：按聊天中提交的方案实施；不包含 npm 发布、Git 提交或推送。

## 行为

- SDK 提供二维码生成、轮询、账号验证；CLI 提供 auth.login/status/logout。二维码及进度写 stderr，最终结果保持 JSON envelope；支持指定本地 PNG。
- 使用 B 站网页扫码协议，等待手机确认。轮询间隔不低于 2 秒，支持取消、超时和过期；不会自动刷新二维码或续期 Cookie。
- 凭据仍由显式 credentialsFile 或 SDK provider 提供。文件存储使用 POSIX 0600 / Windows 当前用户 ACL、同目录临时文件和原子替换。成功验证新账号后才保存；失败保留旧凭据。logout 仅删除本地凭据，不撤销其他设备会话。
- MCP 不增加登录或凭据工具。SDK 登录结果中的 credentials 仅供可信宿主保存，CLI 不序列化它；不返回 Cookie、CSRF、refresh token 或含敏感参数的成功跳转 URL。
- 经过服务端验证的 UID 作为限额和私信游标的账号身份；草稿仍绑定原会话指纹，重新登录须重新准备和审批草稿。状态记录会话指纹到 UID 的已验证映射，不包含 Cookie。
- 旧限额、暂停和游标仅在旧会话可验证时迁移；冲突或无法归属的旧状态不静默丢弃。保留历史草稿与发送结果，不自动重发。账号切换不会转移另一账号的数据。
- 不启动浏览器、桌面输入模拟或外部消息发送。实际扫码须由用户完成，自动验证使用模拟响应。

## 依赖与限制

官方网页脚本核实生成、轮询端点及状态码 0/86101/86090/86038，轮询为 2 秒。未取得真实成功 Cookie，真实账号兼容性必须单独报告。二维码渲染使用 qrcode 的 Node API。首版文件为明文，权限限制不等于加密。

## 验收

状态转换、取消/过期/网络异常；缺少 Cookie 或验证失败不覆盖旧文件；账号切换、同账号新会话限额与游标延续；旧草稿不能由新会话执行；迁移失败原状态不变；输出脱敏；Windows 文件 ACL；CLI 与 MCP 回归、打包独立安装。
