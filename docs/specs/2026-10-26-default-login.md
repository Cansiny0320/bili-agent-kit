# 默认配置与直接扫码登录

用户已批准：CLI 直接运行 `auth.login`，MCP 提供扫码登录入口，默认配置自动初始化，显式 `--config` 保持兼容。README 表格宽度作为补充调整。

## 行为

- CLI、MCP 和 SDK 文件运行时省略配置时，共用用户主目录下 `.bili-agent-kit/config.json`、`credentials.json`、`state/`。与工作目录无关，不扫描或导入旧项目配置。
- 默认配置只在缺失时安全创建；并发初始化不覆盖已有文件；错误配置必须报错。显式配置缺失或错误不得回退默认账户。默认不启用写操作。
- CLI 支持 `[--config <file>] <command> [<JSON|->]`，省略 JSON 使用 `{}`，旧命令兼容。help 不初始化文件。
- MCP 默认无参数启动；新增 `bili_auth_login`、`bili_auth_status`、`bili_auth_cancel`。二维码作为原生 PNG 图片返回，扫码由 B 站 App 确认。状态只返回进度或账号信息，不返回 Cookie、token 或二维码内部 key。
- 已有效登录时保留当前账号，不主动重新登录。二维码等待在有界后台流程运行；重复启动复用当前流程；取消、过期、失败不删除原凭据；连接关闭取消等待。
- MCP 不开放退出、刷新、OAuth、审批或其他管理员接口。嵌入式 `createMcpServer(kit)` 保持兼容，通过可选 auth provider 开启登录工具。
- 媒体和官方应用配置仍为可选项。自动配置不自动启用互动或官方权限。

## 验收与边界

临时目录验证默认初始化、跨进程路径一致、并发创建与显式配置失败；模拟扫码验证 PNG 输出、成功/取消/过期/错误、脱敏和关闭清理；现有身份/审批测试与打包 smoke 通过。真实用户凭据和账号不用于本次测试。README 中英文同步更新；表格采用 GitHub 支持的 HTML 宽度属性并核对渲染。
